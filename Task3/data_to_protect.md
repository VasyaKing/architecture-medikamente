# Реестр данных, необходимость защиты и инструменты

## 1) Персональные данные пациента (PII)

| Данные                                                                           | Почему нужно защищать                                                                     | Инструменты защиты                                                                                                                                                              |
|----------------------------------------------------------------------------------|-------------------------------------------------------------------------------------------|---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| **ФИО, дата рождения, телефон, e-mail**                                          | ПДн по 152-ФЗ. Прямая идентификация личности. Риск кражи личности, мошенничества, утечки. | **Шифрование в DB, **TLS 1.3 / HTTPS** в передаче, **ABAC/RBAC**, **маскирование** в журналах, **ограничение по ролям**, **DLP почты**, **аудит доступа**                       |
| **Адрес прописки, паспортные данные, место работы/учёбы** (особо защищаемые ПДн) | по ФСТЭК/152-ФЗ требует повышенного уровня защиты.                                        | **Криптохранилище**, **шифрование полей**, **HSM/KMS**, **минимизация данных**, **запрет логирования**, **строгий ABAC**, **разрешение только врачам/ресепшену по нуждаемости** |
| **Контракт пациента/договор**                                                    | Включает ПДн + финансовые данные → контроль целостности.                                  | **Шифрование + контроль целостности (HMAC)**, **электронная подпись**, **аудит**                                                                                                |

## 2) Медицинские данные пациента (MED)

| Данные                                                         | Почему нужно защищать                                                              | Инструменты защиты                                                                                                                                                                                                                     |
|----------------------------------------------------------------|------------------------------------------------------------------------------------|----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| **Медицинская карта** (диагнозы, осмотры, назначения, выписки) | По 323-ФЗ – медицинская тайна. Утечка = максимальный репутационный ущерб + штрафы. | **Tagging: patient.medical**, **шифрование в ObjStore**, **заголовочные токены доступа**, **политики PDP (врач → только свои пациенты)**, **аудит 24/7**, **антивирус для документов**, **защита от массового чтения (rate limiting)** |
| **Результаты анализов**                                        | Медицинская тайна, работа с внешней лабораторией увеличивает риск.                 | **mTLS с лабораторией**, **минимизация ПДн (ID вместо ФИО)**, **шифрование в покое**, **контроль импорта**, **аудит**                                                                                                                  |
| **История посещений**                                          | Может раскрыть чувствительную мед. информацию.                                     | **Шифрование БД**, **ABAC**, **аудит**, **TTL на хранение исторических журналов**, **обезличивание при выгрузке в BI**                                                                                                                 |

## 3) Финансовые данные

| Данные                 | Почему нужно защищать                                          | Инструменты защиты                                                                                                                  |
|------------------------|----------------------------------------------------------------|-------------------------------------------------------------------------------------------------------------------------------------|
| **Платёжные операции** | Персональные финансовые данные → защищается по закону и ФСТЭК. | **Шифрование записи**, **разделение доступа (кассир ≠ бухгалтер)**, **TLS**, **аудит операций**, **не хранить полные данные карты** |
| **Данные ККМ**         | Фискальные данные + ПДн на чеке.                               | **Защищённый канал → 1С**, **контроль доступа**, **немодифицируемый лог**                                                           |
| **Учёт в 1С**          | Включает ПДн + финданные → высокий риск.                       | **Шифрование 1С-хранилища**, **ограничение доступа**, **жёсткая ролевая модель**, **Backup в зашифрованном виде**                   |

## 4) Данные сотрудников

| Данные                        | Почему нужно защищать                 | Инструменты                                 |
|-------------------------------|---------------------------------------|---------------------------------------------|
| Паспортные данные сотрудников | Аналоги ПДн пациентов                 | Шифрование, ABAC, отслеживание доступа      |
| Зарплаты                      | Финансовые данные, риск мошенничества | RBAC, контроль целостности, запрет выгрузки |
| Учёт доступа / роли           | Критично для безопасности             | IAM + MFA, защищённое хранение              |

## 5) Данные складского учёта / ТМЦ

| Данные                                   | Почему нужно защищать   | Инструменты                   |
|------------------------------------------|-------------------------|-------------------------------|
| Номенклатура ТМЦ, оборудование, реагенты | Не ПДн, но бизнес-тайна | RBAC, Audit, резервирование   |
| Инвентаризационные акты                  | Частично включают ПДн   | Шифрование + контроль доступа |

## 6) Данные коммуникаций (почта, SMS)

| Данные                | Почему нужно защищать            | Инструменты                                                             |
|-----------------------|----------------------------------|-------------------------------------------------------------------------|
| Уведомления пациентам | Риск передачи ПДн наружу         | **DLP**, **скрытие деталей**, **SMS без медданных**, **DMARC/SPF/DKIM** |
| Почтовые вложения     | Могут содержать сканы документов | **Антивирус**, **DLP вложений**, **запрет пересылки наружу**            |

## 7) Логи и Telemetry

| Данные           | Почему нужно защищать                  | Инструменты                                                       |
|------------------|----------------------------------------|-------------------------------------------------------------------|
| Технические логи | Риск утечки ПДн при логировании DTO    | **Log scrubbing**, **запрет ПДн**, **SIEM**, **анонимизация**     |
| Аудит доступа    | Содержит чувствительную метаинформацию | **WORM-storage**, **подпись лога**, **централизованное хранение** |
