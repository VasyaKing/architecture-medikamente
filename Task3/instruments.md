# Защита данных в разных состояниях

## 1) Защита данных в покое (Data At Rest)

* DB (Postgres: пациенты, записи, медкарты)
* 1С хранилища
* Object Storage (PDF/JPG)
* аналитические хранилища (Raw/De-ID)

| Компонент       | Метод                                                           |
|-----------------|-----------------------------------------------------------------|
| DB              | **TDE + шифрование полей** (`passport`, `address`, `diagnosis`) |
| ObjStore        | **SSE-KMS** + приватные бакеты                                  |
| 1С              | встроенное шифрование через КриптоПро / файловое ACL            |
| Raw Store       | полное шифрование томов + HSM                                   |
| De-ID Store     | хранение уже обезличенных данных                                |
| Резервные копии | шифрование AES-256, хранение вне офиса                          |

## 2) Защита данных при передаче (Data In Transit)

| Поток                     | Защита                             |
|---------------------------|------------------------------------|
| Портал ↔ API Gateway      | **TLS 1.3, HSTS, OAuth2**          |
| Сервисы между собой       | **mTLS**                           |
| Медкарты (файлы)          | передача по S3-протоколу через TLS |
| Интеграция с лабораторией | **mTLS**, минимизация ПДн          |
| ККМ ↔ 1С                  | **TLS/VPN**, проверка подлинности  |
| ETL → Analytics           | VPN + TLS                          |

## 3) Автоматизированный контроль

| Инструмент                  | Назначение                                    |
|-----------------------------|-----------------------------------------------|
| **Splunk**                  | корреляция событий безопасности               |
| **DLP**                     | контроль почты, файлов, загрузок, копирования |
| **Reverse-proxy**           | контроль доступа из облаков                   |
| **WAF** перед API Gateway   | защита API                                    |
| **OPA (Policy Engine)**     | автоматизированные политики доступа           |
| **Data Tagging Service**    | проверка, что каждое поле имеет тег           |
| **Static Privacy Analysis** | автоматическая проверка DTO/схем на риск ПДн  |
| **CI/CD Privacy Checks**    | тесты: не утекли ли сырые данные              |

## 4) Реестр программных и аппаратных средств

_**Программные средства:**_

* Keycloak
* OPA
* HashiCorp Vault или Yandex KMS / AWS KMS (ключи)
* MinIO/S3 совместимое хранилище (защищённое)
* Postgres + pgcrypto
* Elastic/Splunk для аудита
* Reverse-proxy/Nginx + WAF
* TLS сертификаты (Let's Encrypt / ГосСерты)
* GitLab CI Privacy Rules (защита в pipeline)
* ETL (Airflow)

_**Аппаратные средства:**_

* HSM (Rutoken HSM / JaCarta HSM / CryptoPro HSM)
* Серверы хранения резервных копий
* VPN-шлюз
* Failover firewall (Fortigate / Cisco ASA)
* Сегментация сети (VLAN)

# Итоговая сводная таблица

| Данные                     | Необходимость защиты                       | Инструменты                                    |
|----------------------------|--------------------------------------------|------------------------------------------------|
| ПДн пациента               | Закон (152-ФЗ), риск утечки, мошенничество | Шифрование, TLS, RBAC/ABAC, DLP, аудит         |
| Медицинская карта          | Медицинская тайна (323-ФЗ), критичный риск | Теги, PDP, шифрование файлов, антивирус, аудит |
| Результаты анализов        | Медтайна, внешняя интеграция               | mTLS, минимизация ПДн, шифрование              |
| Платежи, фискальные данные | Финданные, связь с ПДн                     | Шифрование, ролевая модель, аудит              |
| Данные сотрудников         | ПДн + бизнес-тайна                         | ACL, шифрование, MFA                           |
| Логи и аудит               | Чувствительные метаданные                  | SIEM, WORM-storage                             |
| BI/ML данные               | Не должны содержать ПДн                    | Обезличивание, анонимизация, ETL-контроль      |
